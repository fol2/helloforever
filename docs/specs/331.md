# Spec: #331 History in the companion

Status: **lead design, 23 Nov 2026** (the owner: the design is the lead's to decide). Roadmap line 16.

## 1. Aim

The companion (`hellolink assist`) knows only the current UI session: the strip. The addon's
saved data keeps every fight the budget allows, and this repository has no reader for it
(`docs/specs/115.md`, section 7). This spec adds one, in Rust, and one use of it: the
`session` card's "slowest against usual" stands on the character's whole history, not only
on the last 10 fights the addon keeps per enemy (`docs/SCHEMA.md`, "Fight baseline").

It also makes `docs/SCHEMA.md` checkable in public: the reader fails, with the place, on any
part of the file it does not know how to read.

## 2. What is read

`HelloForeverDB` in `WTF/Account/<account>/SavedVariables/HelloForever.lua`, read once, whole.
For each `characters[<key>]`:

- `guid` (string, optional);
- `baselineResetAt` (number, optional);
- `fightLog.days[<day>]` = `{ keys = { <fight key>, ... }, data = { <blob>, ... }, ... }`:
  `keys[i]` is the key of the record in `data[i]`. Both are lists 1 to n with no gap and no other key; a gap
  is an error, so it cannot hide the records after it.

Other fields are read as Lua values and not used.

### The Lua the client writes

A subset, enough for the files this client writes: `<name> = <value>` statements, where a
value is a table constructor (`{ [<key>] = <value>, <value>, ... }` with `,` or `;`), a string
in double quotes with Lua 5.1's escapes (`\n \r \t \a \b \f \v \<newline> \ddd` up to 255; any
other escaped character is itself, as Lua 5.1's lexer reads it), a finite decimal number (a
sign, a fraction, an exponent; an overflow such as `1e309` is refused), `true`, `false` and `nil`. Lines end in
CRLF or LF; comments (`--` to the end of the line) are skipped. Anything else is an error
that names the line and column. A file that ends inside a value is an error ("cut short"),
never a shorter table.

Measured on this machine's file (4.4 MB, 23 Nov 2026): CRLF line ends, no comment, no
backslash, no infinite or NaN number. How the client writes an infinite number is not known,
so the parser does not guess one: it refuses it, with the place.

### Blobs

`d1:` + Base64 (standard alphabet, `=` padding, padding bits zero: RFC 4648, section 3.5) of
raw Deflate of JSON, the stream ended and no byte after it; `j1:` + JSON text
(`docs/SCHEMA.md`, "Integrity rules for importers"). Any other prefix, a bad Base64, a
Deflate stream that does not end, or JSON that does not parse is an error naming the
character, the day and the fight key. A record whose own `key` is not the key it is filed
under is an error too (the same rules).

## 3. Which fights count, and the usual time

The addon's rule, unchanged (`docs/SCHEMA.md`, "Fight baseline", "Which fights count";
`HelloForever/Fights.lua`, `baselineOf`): a fight record with `pull.start.level` a number,
no `pull.approx`, no level change, exactly one row in `types.EnemyDamageTaken.combatSources`
with a `sourceCreatureID` above 0. Its key is `<creatureId>:<pull.start.level>`; its time is
`dur` when it is a finite number above 0, else unknown. As in Lua, a `false` value is no value: a
`pull.stop.level` of `false` falls back to the record's `lvl`, and an enemy name that is not
text falls back to the record's `name`.

- **Each fight once, by its last revision.** One fight key can be in two records of one
  character (`docs/SCHEMA.md`, "Character key": an earlier revision stays in the `<name>-`
  record). Of the records joined, the one with the highest `rev` decides whether the fight
  counts and its time.

- A fight that started before the character's `baselineResetAt` does not count (for joined
  records, the latest reset of any of them): a reset in
  the game means the earlier fights are no longer the player's usual (`/hello baseline reset`).
- The **usual time** of a key is the median of the known times of its counted fights, as the
  addon's `median` (the mean of the two middle values for an even count), when at least 3
  are known (`BL_MIN`); otherwise the key has no usual time (decision 5 of `docs/specs/115.md`:
  unknown gives no card).
- Unlike the addon's baseline, every counted fight is used, not only the last 10.

## 4. The command

```sh
hellolink history <HelloForever.lua>
```

Prints one JSON object: for each character key, `{ "guid", "fights", "counted", "keys": {
"<creatureId>:<level>": { "name", "n", "usual" } } }` (`fights`: the records read; `counted`:
those that count; `n`: the counted fights of the key with a known time; `usual`: whole
seconds, rounded as the strip rounds, or `null` under 3). Keys are sorted, so the output of
one file is the same every time. Exit status 1 with the error on stderr when the file
cannot be read.

## 5. The companion

`hellolink assist --history <HelloForever.lua>` reads the file once, at start. The character's
records are those whose `guid` equals object 10's `guid`, and those with no `guid` whose key's
name part (before the last `-`) equals object 10's `name` (`docs/SCHEMA.md`, "Character key":
one character can have a `<name>-` record beside its `<name>-<realm>` record, and an importer
joins them by name). A record with another `guid` is never joined. When object 10's `guid` is
`null`, only the records with no `guid` of its name are joined. Until object 10 is read,
no usual time comes from the history.

For the `session` card's slowest enemy, a fight's usual time is the history's usual time of
`<id>:<level>` (object 12), leaving out the fight itself (by its key), when the history has
one. Otherwise it is object 12's own `dur[1]`, as now. So an enemy the strip has no usual
time for (under 3 earlier fights this session) can be the slowest when the history has one.
When the slowest enemy's usual time came from the history, the card's `basis` adds " and N
saved fights" (Cantonese " 同 N 場存咗嘅戰鬥"), N being the saved fights behind that usual time.
Without `--history` nothing changes.

The file changes only at a reload or a logout, and the session's own fights reach it then.
The companion does not read it again. (ponytail: read once at start; read again on a newer
modification time if a long session shows a need.)

A file that cannot be read stops `assist` at start with the error: a flag the owner set must
not be dropped in silence.

## 6. Out of scope

Writing the file; the trimmed days' receipts; gaps; snapshots, quests, the pet; other cards.
They read the same parser when an intent asks for them.

## 7. Tests

- **Hand-written file** (`reader/hellolink/tests/data/history/`): fake names only
  (`FakeHunter`, `TestRealm`), both key forms of one character (`FakeHunter-` with no guid and
  `FakeHunter-TestRealm` with one), a `baselineResetAt`, one `d1:` blob whose Base64 is written
  out by hand from a stored Deflate block (LESSONS: check an encoder against bytes written by
  hand), and `j1:` blobs. The summary is compared with a committed expected file, byte for
  byte.
- **Refusals**: the file cut short, an unknown blob prefix, a bad Base64, a key filed under the
  wrong name, a value the subset does not know: each fails, and the message names the place.
- **The companion**: a set of events with object 10 and object 12 and the hand-written file:
  the slowest enemy uses the history's usual time and the basis says so; without the flag the
  card is as before; a fight in the history with the same key as object 12's is left out.
- **Local check** (not in CI): this machine's file is read whole, every blob, in under 2 s;
  the counts go in the PR, no names.
