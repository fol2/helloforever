# Spec: #93 A baseline for a fight

After a fight the player sees how it went against the usual fight with the same enemy at
the same level: "Defias Thug, 12 s, usual 15 s (8 fights)". The usual fight is the
baseline. It is the next step of the assistant (`docs/north-star.md`, priority 3): what the
game saved comes back to the player as advice, in the game.

Status: draft for build. Nothing here is built yet.

## 1. Decisions

1. **The addon computes the baseline from its own fights.** It works for anyone who installs
   HelloForever, with no pipeline and no private data. The offline report in wow-data stays
   as it is. (Lead's decision; owner, 12 Nov 2026: "你係 project lead，你可以決定".)
2. **A baseline belongs to one enemy at one player level.** The key is
   `<creature id>:<player level>`. A creature at another level of the player is another
   matchup: levels change damage and time to kill a lot in the first 60 levels. The level is
   the one at the start of the fight, `pull.start.level`, and only when the pull block is not
   approximate (`pull.approx` is not set). `rec.lvl` is not used: the addon reads it when it
   reads the record, which can be after a level up or after a later login. A fight without a
   reliable start level is not counted.
3. **Only fights with one enemy count.** A fight is counted when the client's
   `EnemyDamageTaken` lists exactly one enemy, and that enemy has a creature id. A fight with
   two or more enemies would mix matchups; it is shown without a baseline.
4. **The usual value is the median of the last 10 fights of the key.** A median does not
   move much when one fight went badly; the last 10 follow the player's gear and talents.
   Each number has its own median, over the fights in which that number is known; with an
   even count the median is the mean of the two middle values. A number is compared only
   when at least 3 earlier fights know it. A fight is compared against the fights before it
   (at most 10), and only then added; the oldest leaves when an eleventh comes in.
5. **Numbers, all from the fight record the addon already saves:**
   - `dur`: the fight's length in seconds (the record's `dur`), known when it is a number
     greater than 0;
   - `dps`: the player's `DamageDone` total divided by `dur` (not `amountPerSecond`: it
     drifts while the client's clock runs), known when the total is a number of at least 0
     and `dur` is known;
   - `taken`: the player's `DamageTaken` total, known when it is a number of at least 0;
   - `died`: known when the record has the player's `Deaths` row; true when that row has a
     death recap id that is not 0.
   The raw record is read, not `summarize`'s row: the row turns a missing total into 0 and a
   missing death into false. A missing number is `nil` in the stored fight, never 0.
   The pet's damage is in the player's total, as the record has it. Mana or focus spent is
   not in the record (`pull` keeps no current values: they are secret), so no baseline of
   it.
6. **No secret value is used.** The numbers come from the record after the fight, which the
   addon already saves as plain numbers. The baseline code calls no client function.
7. **Advice, not automation.** One chat line after a fight, off by default, on with
   `/hello baseline on`. And a strip object for local programs (section 4).

## 2. Storage (`docs/SCHEMA.md` gains a section)

```
characters[key].baseline = {
  ["<creatureId>:<level>"] = { name = "Defias Thug", t = <last time>,
                               fights = { { key, dur, dps, taken, died }, ... } },  -- at most 10, oldest first
}
```

- At most 200 keys a character. When a new key would pass 200, the key with the oldest `t`
  goes. A full table is about 290 KiB in LuaJIT's memory (a synthetic table, measured in
  review; not measured in the client or on disk).
- Each stored fight carries the fight's `key`. A key is updated in `summarize`
  (`HelloForever/Fights.lua`) for every record that is not a gap: a new fight is added, and a
  later revision of the same fight replaces its stored fight (found by the fight's `key`).
  A revision that no longer counts (a second enemy came in, the start level is not reliable)
  removes the stored fight. So a fight is in the table at most once, as its last revision
  says. The chat line and the strip object come only for a new fight (`isNew`).
- `/hello baseline reset` empties the table. A fight never changes the table twice.

## 3. What the player sees

After a counted fight, with `/hello baseline on`, one line:

    Defias Thug (lvl 14): 12 s, usual 15 s · 38 dps, usual 31 · taken 210, usual 340 (8 fights)

- A number that fewer than 3 earlier fights know is shown without its usual value. With no
  number to compare: `Defias Thug (lvl 14): first fights, 2 so far`.
- A death: `... DIED (usual: 0 of 8 died)`.
- No line for a fight with more than one enemy, or without a creature id.
- The usual values are the median of the earlier fights, not counting this one.

## 4. The strip object

Object 12, `baseline`, for local programs (the shared reader, `docs/STRIP.md`):

    {"fight": "<fight key>", "rev": 1, "id": 1984, "level": 14, "name": "Defias Thug",
     "dur": [12, 15, 8], "dps": [38, 31, 8], "taken": [210, 340, 8], "died": [false, 0, 8]}

Each triple is `[this fight, usual, how many earlier fights know it]`; `usual` is `null`
under 3. `died` is `[this fight, how many of the earlier fights died, how many know it]`.
A value this fight does not know is `null`. `fight` and `rev` name the fight, so two fights
with the same numbers are two versions of the object. `null` before the first counted fight
of the session, and after `/hello baseline reset`. Sent when a counted new fight is saved.
With twelve objects an object is stale after 43.2 s at the default `dwell` of 0.1 s
(`3 x 12 x 12 x dwell`); the reader's object count changes with it. Agreed with the local
program before it is built, as every format change.

## 5. Build steps, each its own pull request

1. **Record.** `Fights.lua` keeps `baseline` (section 2). Tests in the fights harness:
   one enemy counted; two enemies not; a revision that changes `dur`, adds a death or adds
   a second enemy replaces or removes the stored fight; a level up between the fight and its
   read keeps the start level; no reliable start level, not counted; the ring of 10 and the
   eleventh fight; the cap of 200 keys; `dps` from the total; missing and failed fields
   stored as missing, never as zero; an empty table. Game check: after five fights with one
   kind of enemy, the saved data has that key with five fights.
2. **Show.** The chat line and `/hello baseline on|off|reset`. Tests: the line's numbers are
   medians of the earlier fights, an even count included; fewer than 3; a number known in
   only some fights; a death; the eleventh fight compared with the ten before it. Game
   check: the line after a fight.
3. **Strip.** Object 12, after the local program agreed. Tests as for objects 7 to 11, with
   one vector; two fights with the same numbers give two versions; reset and reload give
   `null`; the stale time at another `dwell`.

## 6. Not in this spec

- Fights with several enemies (a baseline per group of enemies).
- Baselines across characters, or from wow-data's history.
- Advice in words ("you were slower because ..."): that needs the reasons, and AI is later
  (priority 3, then AI; an AI call needs an approved expenditure).
