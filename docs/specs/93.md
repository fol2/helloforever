# Spec: #93 A baseline for a fight

After a fight the player sees how it went against the usual fight with the same enemy at
the same level: "Defias Thug, 12 s, usual 15 s (8 fights)". The usual fight is the
baseline. It is the next step of the assistant (`docs/north-star.md`, priority 3): what the
game saved comes back to the player as advice, in the game.

Status: draft for build. Nothing here is built yet.

## 1. Decisions

1. **The addon computes the baseline from its own fights.** It works for anyone who installs
   HelloForever, with no pipeline and no private data. The offline report in wow-data stays
   as it is. (Lead's decision; owner, 12 Nov 2026: "你係 project lead，你可以決定".)
2. **A baseline belongs to one enemy at one player level.** The key is
   `<creature id>:<player level>`. A creature at another level of the player is another
   matchup: levels change damage and time to kill a lot in the first 60 levels.
3. **Only fights with one enemy count.** A fight is counted when the client's
   `EnemyDamageTaken` lists exactly one enemy, and that enemy has a creature id. In wow-data,
   584 of 752 fights have one enemy; 161 have two or more and would mix matchups. A fight
   with more enemies is shown without a baseline.
4. **The usual value is the median of the last 10 fights of the key.** A median does not
   move much when one fight went badly; the last 10 follow the player's gear and talents.
   A baseline is shown only from 3 fights on.
5. **Numbers, all from the fight record the addon already saves:**
   - `dur`: the fight's length in seconds (the record's `dur`);
   - `dps`: the player's `DamageDone` total divided by `dur` (not `amountPerSecond`: it
     drifts while the client's clock runs, as the wow-data report found);
   - `taken`: the player's `DamageTaken` total;
   - `died`: the player died (`Deaths`, as `summarize` reads it).
   The pet's damage is in the player's total, as the record has it. Mana or focus spent is
   not in the record (`pull` keeps no current values: they are secret), so no baseline of
   it.
6. **No secret value is used.** The numbers come from the record after the fight, which the
   addon already saves as plain numbers. The baseline code calls no client function.
7. **Advice, not automation.** One chat line after a fight, off by default, on with
   `/hello baseline on`. And a strip object for local programs (section 4).

## 2. Storage (`docs/SCHEMA.md` gains a section)

```
characters[key].baseline = {
  ["<creatureId>:<level>"] = { name = "Defias Thug", t = <last time>,
                               fights = { { dur, dps, taken, died }, ... } },  -- at most 10, oldest first
}
```

- At most 200 keys a character. When a new key would pass 200, the key with the oldest `t`
  goes. 200 keys x 10 fights x 4 numbers is a few tens of kilobytes.
- A key is updated in `summarize` (`HelloForever/Fights.lua`), only for a new fight
  (`isNew`: not a later revision of the same fight), only when the fight is whole (not a gap).
- `/hello baseline reset` empties the table. A fight never changes the table twice.

## 3. What the player sees

After a counted fight, with `/hello baseline on`, one line:

    Defias Thug (lvl 14): 12 s, usual 15 s · 38 dps, usual 31 · taken 210, usual 340 (8 fights)

- With fewer than 3 earlier fights: `Defias Thug (lvl 14): first fights, 2 so far`.
- A death: `... DIED (usual: 0 of 8 died)`.
- No line for a fight with more than one enemy, or without a creature id.
- The usual values are the median of the earlier fights, not counting this one.

## 4. The strip object

Object 12, `baseline`, for local programs (the shared reader, `docs/STRIP.md`):

    {"id": 1984, "level": 14, "name": "Defias Thug", "count": 8,
     "dur": [12, 15], "dps": [38, 31], "taken": [210, 340], "died": [false, 0]}

Each pair is `[this fight, usual]`; `died` is `[this fight, how many of the counted fights
died]`. `null` before the first counted fight of the session. Sent when a counted fight is
saved. With twelve objects an object is stale after 43.2 s. Agreed with the local program
before it is built, as every format change.

## 5. Build steps, each its own pull request

1. **Record.** `Fights.lua` keeps `baseline` (section 2). Tests in the fights harness:
   one enemy counted; two enemies not; a revision not counted twice; the ring of 10; the
   cap of 200 keys; `dps` from the total; a record with missing fields counted as missing,
   never as zero. Game check: after five fights with one kind of enemy, the saved data has
   that key with five fights.
2. **Show.** The chat line and `/hello baseline on|off|reset`. Tests: the line's numbers are
   medians of the earlier fights; fewer than 3; a death. Game check: the line after a fight.
3. **Strip.** Object 12, after the local program agreed. Tests as for objects 7 to 11, with
   one vector.

## 6. Not in this spec

- Fights with several enemies (a baseline per group of enemies).
- Baselines across characters, or from wow-data's history.
- Advice in words ("you were slower because ..."): that needs the reasons, and AI is later
  (priority 3, then AI; an AI call needs an approved expenditure).
